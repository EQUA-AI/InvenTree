The equivalent YAML keys are `aimms_work_orders_enabled: true` and `aimms_job_kits_enabled: true`. Restart the local app to reload its settings. Frozen identities in `tasks/services/procurement.py`:

| Event | Producer |
|---|---|
| `PROC_SOURCE_SELECTED` | P1 source command |
| `PROC_PO_LINKED` | B04 validated native PO/line binding, referencing the source event |

All names fit the existing 40-character column. They are Work evidence events, not native PO states. P1 produces only source and acknowledgment events; the other producer contracts are frozen for the next lanes, not claimed as implemented effects.

`operation_key` is an opaque nonblank string of at most 128 characters. Generate it once per intentional operation, retain the exact payload/key through reload and retry, and use a new key only for a new intent. Uniqueness is the existing database constraint on `(work_order, WorkOrderCommand.idempotency_key)`, not the event's indexed key. Commands lock the Work row, authorize the current actor, and check replay before checking stale versions/native preconditions. Canonical request hashes include the actor and normalized body. Identical authorized replay returns the original event; a changed body or different actor under the same key conflicts. Event and command insertions commit together. A second deliberate source decision must explicitly supersede the latest source event on the current machine.

Every P1 snapshot retains `actor: {pk, label, kind: 'internal_person'}`, `authority: 'evidence_only'`, and `approval_policy: 'named_approver_per_po'`. The recorded actor is a person recording evidence; this does not identify a PO approver. B04 must retain the actual native approval ID, named approver and approved revision/baseline. No service-identity purchase authority or approval-free placement was added.

## B02: additive shared read contract

Existing endpoint, with native Work visibility/role checking retained:

```text
GET /api/tasks/work-orders/{work_pk}/materials/
```

Its original requirements/reservations/usage fields remain. New `procurement` is `MaintenanceProcurementContext` from `src/frontend/lib/types/Procurement.ts`; `materials.ts` has only an additive optional type field. No UI implementation changed.

The r8.1 object contains:

- `schema_version`, `work_order_id`, `work_lifecycle_version`, `kit_version`; Work and kit tokens remain distinct.
- `purchasing_visible`, `stock_visible`, fixed `approval_policy` and `email_policy: 'recorded_only'`.
- `lines[]`, keyed by both native `kit_line_id` and existing UUID `key`.
- `pending_operations[]`: unresolved `procurement_*` ledger commands, with original `idempotency_key`, status and result reference; suppressed without stock authority.

Each line carries the native Part/base UOM and required quantity, `requirement_version` (JobKitLine.version), a requirement fingerprint, a configuration fingerprint, original Work date-only `work_due_date`, and separately sourced `needed_at`/`dependent_step`. The configuration fingerprint hashes actual machine identity/model/serial/profile, component assignments and the kit's procedure snapshot hash; it is an optimistic token **not an OEM revision or proof of fit**. The requirement fingerprint additionally detects quantity, source snapshot and due-date drift. Historical selection stays visible with `selection_current: false` after drift; its obsolete deadline is not projected as the current requirement. Quote validity and technical eligibility remain explicit source facts; version currency alone does not authorize a purchase.

`source_selection` is an event envelope. `orders[]` uses actual shortage links or durable exact PO/line events, so deleting/resolving a shortage does not erase retained history. A native PO retains its native status/reference, supplier/SupplierPart, order and received quantities, extra-line IDs, goods/charges/complete totals and currency. Native `packaging`, `base_uom` and `base_units_per_order_unit` remain separate. `order_uom` is supplied only from a current matching source offer; native descriptive packaging is never promoted to a unit. Acknowledgment quantities explicitly use native supplier order units, retaining the native base conversion and an unknown textual UOM when it is not sourced. Values use native Decimal/Money conversion and native discounts. Freight is included once as an extra line. Unknown price or missing FX produces null, never a misleading zero. `native_recorded_total` is also retained independently, since native cached totals can omit unknown amounts.

`placed` reflects the actual native `issue_date`, with `precision: 'date'` and unknown actor; no midnight or approver is invented. `binding` projects the separately recorded exact B04 event, where the real approval/placement actor and instant can be retained. `recorded_email` is independent and can only yield `recorded_only`, never provider acceptance or delivery. `acknowledgment` retains the explicit original acceptance. `acknowledgment_current` compares the captured native commercial baseline, including all goods, charges, discounts, currency, supplier and target date; later edits retain the historical acknowledgment but invalidate its current applicability.

`receipts[]` projects only receipt events tied to this exact kit line **and** actual PO/line; it never guesses using Part, stock recency or a shared PO. The immutable snapshot carries returned stock IDs, quantity-at-receipt, batch/location/status and before/after received quantities. B07 must produce these snapshots from its actual native response in the receipt transaction. Current allocations and their physical custody/usage remain in the existing Materials response. Additional Decimal `reserved_quantity` (reserved/staged), `issued_quantity`, `used_quantity` (consumed) and `outstanding_quantity` buckets are disjoint. Receipt is never added to fulfillment twice, and consumption never becomes free stock or a new demand.

Permissions are enforced before procurement joins. Shared Work requires independent current machine authorization plus Purchase Orders view to receive procurement context. Stock identifiers/receipt snapshots additionally require Stock view. Without purchasing authority, `lines` is empty and even the legacy shortage `purchase_order_line` ID is redacted. The generic Work event serializer also redacts `PROC_*` metadata for unauthorized/foreign-machine readers and receipt metadata for readers without stock access. Thus the audit timeline is not a bypass. Reads perform no saves, reserve, receiving or continuation calls.

## B03: immutable source selection

```text
POST /api/tasks/work-orders/{work_pk}/procurement/source-selection/
```

Input is `ProcurementSourceCommand` / `SourceSelectionSerializer`. Full field definitions are in the shared TypeScript type and server serializer; the package's proposed camelCase DTO was deliberately adapted to the existing snake_case Materials wire format.

Required body fields:

```text
operation_key, expected_version, kit_line_id, source_at, provenance,
requirement_version, configuration_revision,
needed_at (nullable), deadline_source (nullable), dependent_step (nullable),
technical_evidence[], offers[], selected_offer_key, reason,
supersedes_event_id (nullable for first decision)
```

Provenance is `{mode: live_test|recorded_fixture, method: human_review|recorded_document|model_execution, reference, fixture_namespace}`. The namespace is required only for fixtures. A preloaded recorded document remains recorded evidence; it is not relabeled as a fresh model execution.

Each PDF reference is `{attachment_id, sha256, page, revision}`. The native attachment must belong to this Work/machine (or affected PO for acknowledgment), contain retained PDF bytes rather than a URL, match SHA-256, parse as a PDF and contain the cited page. Existing native attachment access/download remains authoritative; no alternate public file URL is exposed. The event preserves references/hashes; it does not make otherwise editable native attachments immutable or add a second document store.

Offers retain `key`, SupplierPart, quote/revision, exact order quantity/UOM and native pack conversion, unit price, absolute discount, freight, tax, other charges, delivered total/currency, terms, promise/basis, validity, technical eligibility and source PDF. Supplier/Part/SKU/base UOM are snapshotted from actual native records. Active supplier, active SupplierPart and active purchasable matching internal Part are checked. The selected quantity/conversion must cover the requirement. Complete Decimal totals must reconcile; incomplete costs require an unknown delivered total. Known zero stays zero. Unknown terms/promise/validity stay null.

The command records the decision; it does not claim an unresolved fit is approved or place an order. B04 must independently validate the current selected fit, quote validity, deadline, native prices/full charges and named approval before any purchase effect.

## B06: explicit acknowledgment

```text
POST /api/tasks/work-orders/{work_pk}/procurement/acknowledgment/
```

`ProcurementAckCommand` / `AcknowledgmentSerializer` requires the common operation/version/line/source-time/provenance fields plus `purchase_order_line_id`, `supplier_reference`, `accepted_quantity`, `terms`, `promised_at`, original `source` PDF and `deviations[]`.

The service checks this kit's actual linked shortage/PO line, actual Part/SupplierPart/supplier identity and quantity not exceeding the native line. It locks the PO header before the native line, snapshots the native commercial baseline and appends a new event. Partial acceptance remains partial in its explicit quantity; no whole-order confirmation is inferred. Supplier source time and promise are distinct from event ingestion time and the Work's needed-by requirement. Native supplier reference is not overwritten. Native placement, a recorded email or a generic reply never creates this event. Later acknowledgment corrections append new facts using new operation keys.

Both commands return HTTP **200** for first execution and identical replay:

```text
{event_id, operation_key, event_type, source_at, recorded_at,
 actor: {pk, label, kind}, snapshot: {...}}
```

ISO instants keep an explicit timezone even under Django's naive SQLite test configuration. Native date-only fields remain dates. Unknown/misspelled fields and malformed payloads return 400, permission denial 403, scope/disabled features 404, and stale version/request-key conflicts or domain preconditions 409 with `{code, detail}`. Successful responses use `Cache-Control: no-store`. OpenAPI documents command request fields and the event response envelope.
