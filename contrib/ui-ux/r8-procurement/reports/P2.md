## B04: implemented

- Corrected the raw AI add-line tool: resolve one active SupplierPart for the actual
  PO supplier/internal Part, honor an explicit SupplierPart choice and send that PK
  as native `part`. Reject ambiguous, inactive or mismatched choices. Preserve zero
  explicit price, disable auto-pricing for reviewed prices and disable merging.
- Governed issue accepts native Extra Lines, includes discounted goods **and all
  charges** in its total, and snapshots their IDs, quantities, prices, currencies,
  discounts and references. Baselines retain every header/goods/charge database
  field, including charge context. Parent, goods, charges, supplier, SupplierParts
  and internal Parts are locked/rechecked for execution. Native total readback must
  agree with the reviewed total.
- Added `place_purchase_order`: one durable approval operation atomically creates
  native goods/charges and places the PO. The assigned **named authenticated person**
  must approve on screen with current review/purchasing/line/charge permissions.
  No service identity, voice placement or approval-free executor is added. Exact
  prices are preserved through canonical serializers/state transitions.
- Reused ApprovalExecution/ExecutedEffect and approval events for actor/result
  receipts and replay. Purchase request hashing rejects different instructions
  under one stable key with HTTP 409; matching creation replay is resolved before
  mutable native validation, including after the PO is Placed. Reapproving the
  same execution returns its first result. Failure rolls back PO, goods and freight.
- Combined recorded placement suppresses native internal order notifications and
  never sends supplier mail. Existing legacy issue retains native internal
  notification semantics; it still never establishes supplier email.
- Shortage linking now enforces Work/machine scope, kit authority, purchasing read
  access, native Placed state, matching active supplier/selected Part, known price
  and sufficient unreceived quantity after other linked shortages, using actual
  supplier pack conversion. A repeated shortage/PO-line link adds no effect.
  Pending/unvalidated lines cannot newly mark a shortage Ordered. Existing receipt
  and reservation reconciliation remains P3's responsibility.

## B05: implemented

- Removed legacy generated-document sample-data fallback. Missing source/reference
  fails before rendering/sending. Legacy PO generate-and-send is refused in favor
  of the native record-only operation.
- Added exact native PO render-context assembly with explicit buyer, receiving
  street, recipient, provenance and current native commercial facts. Supplier
  postal address is distinct from ship-to. Unknown standalone tax remains null;
  zero is preserved when explicitly provided to supported templates.
- Jinja quantities preserve native decimal precision; Decimal formatting replaces
  float formatting. PO/RFQ templates display known zero prices/tax, use EQUA AIMMS
  branding, show native status text and render native freight once as an Extra
  Line. A fixture is marked as representative; the PO document states recorded
  only and not sent. No supplier acknowledgment/payment/physical use is inferred.
- New immutable `PurchaseOrderDocumentEvidence` stores exact PDF bytes, exact MIME
  email bytes (including that PDF), full render/email context, SHA256 hashes,
  operation/request identity, actual actor and recording time. Globally unique
  operation key plus parent lock guards replay. Recording makes database writes
  only; no SMTP/provider/file-store write is invoked. Later PO edits never rewrite
  earlier evidence. Reconciliation checks stored hashes and attachment bytes,
  filename/type and returns a known `verified`/`corrupt` attachment state with
  `recorded_not_sent` communication state.
- Existing **read-only** Gmail reconciliation now verifies attachment filename,
  MIME type, SHA256 and multiplicity, returning success for exact matches and
  unknown for mismatches without sending/retrying. Provider operations in its
  tests are mocks; no external account was contacted.

## Contracts for U1/U2 and coordinator

Complete fields, payload examples, endpoints, events, permissions and replay rules
are in [contracts/p2.md](../contracts/p2.md).

- Existing `POST /api/approvals/` with `action_type=purchase_order`, stable
  `agent_run_id`/`tool_call_id`, `assigned_to_user_id` and prepared placement payload;
  existing open/confirm-viewed/approve lifecycle performs the named screen decision.
  Additive payload operation is `place_purchase_order`, with `line_items`,
  `extra_lines`, currency and explicit reviewed total. Server supplies identities,
  pack/UOM, goods_total and charges_total.
- Receipt adds `charge_ids`, `total`, `currency`, `approved_by_id` and `approved_by`
  to native order/reference/status/line IDs. `supplier_email_sent` remains false.
  Existing durable approval events/execution records are reused; P2 emits no new
  Work event type. B02/B03 can join these facts without inventing `PROC_PO_SENT`.
- `POST /api/order/po/{pk}/recorded-evidence/` takes operation_key, to,
  from_address, ship_to, buyer_name, provenance_kind (`native_record` or `fixture`)
  and optional internal_ref. HTTP 201 first record, 200 replay, 409 changed input,
  400 preparation failure. It requires native purchase change and email-evidence
  permission; it does not require or borrow provider-send authority.
- `GET` lists that PO's evidence; `GET ?operation_key=...` returns the exact
  pdf_base64/email_base64 as well as context/hashes. Native purchasing and
  users.view_email permission are rechecked, including on replay. Output contains
  state=`recorded_not_sent`, supplier_email_sent=false, attachment_state and actual
  recording/actor facts, with no provider ID or invented sent time.
- Existing shortage link endpoint and body are unchanged. Its validated PO-line FK
  remains the handoff to P1/P3. Materials reads are untouched and stay read-only.
