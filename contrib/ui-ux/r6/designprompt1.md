# designprompt1 — EQUA AIMMS Frontend Excellence

**Standing user instruction:** applies to all EQUA AIMMS UI screen development, not just one sprint or screen. Recorded 18 October 2026.

Automatically select and apply the most relevant installed EQUA frontend, UX, visual design, React, telemetry, and QA skills. Use GitHub, Context7, Product Design, and MagicPath where valuable; do not introduce a tool or external integration merely to satisfy a checklist.

Inspect the actual codebase, design system, and workflows before making changes. Preserve React, TypeScript, Mantine, and InvenTree architecture. Prioritize exceptional desktop UX, premium visual design, intuitive workflows, operational clarity, information density, consistency, accessibility, and performance, while respecting EQUA's safety and authorization requirements.

Deliver production-quality implementations, not just designs or plans. Reuse existing components, avoid unnecessary dependencies, inspect rendered screenshots, run relevant tests, and iteratively refine until the highest-impact issues are resolved. Report actual verification results and remaining gaps. **No Figma.**

## Execution rules

- Read applicable installed skills before their work; choose the smallest relevant set rather than loading every skill.
- Start from actual native routes, types, providers, roles and theme tokens. Do not invent domain facts, readiness, service authority, telemetry, tenant scope or successful writes.
- Preserve explicit native-presentation constraints, including the R6 prohibition on redesigning Machine Details/header or replacing the existing assistant.
- Validate desktop density and hierarchy first, then phone/tablet containment, keyboard/focus, long and missing values, loading, stale data, denied access, successful empty results and failure recovery.
- Inspect real captures of the implemented components. Fix high-impact findings and replay focused tests before broader regression checks.
- Keep task, backlog, contract and evidence records current. Distinguish isolated source/fixture validation from real login, storage, deployment, human/domain approval and product acceptance.
- Continue with the next unblocked task when a bounded implementation slice is verified. Keep unresolved owner decisions explicit; do not waive dependencies or falsely close acceptance gates to keep moving.
