Implementation order after prerequisite review: reuse native types at a real consumer; add the smallest pure projection needed; preserve the complete source alongside display values; verify missing/denied data, zeros/units/clocks and stable query keys. Avoid unused projection helpers merely to fill the plan.

`suppliedTrends.ts` is the first such seam. Its unit tests check raw-object preservation; its new browser checks exercise the real table/sparkline query ownership. Neither test suite establishes completed P02 acceptance or corrected S3 rendering.

## Implemented consumer checkpoint

- `boardCardIdentity` is used by MaintenanceBoard; card identity remains distinct from owning work across divergent IDs and multiple cards per work.
- `projectCloseoutWorkOrder` is used by WorkOrderDetail and preserves canonical id/title/reference/lifecycle/version, including empty reference and version0. The WO-id fallback is display-only. Completion never invents service or external-delivery status.
- `lib/types/Closeout.ts` replaces duplicate local native interfaces without defining a new wire schema. CloseoutPanel still reexports its existing work-order type for callers. Existing Asset/Repair/Tasks/Overview types remain authoritative.
- Seven new projection tests, 44 total pure units, S0 types and 95 synthetic browser cases pass. Request/criterion/authority/service/media projections remain unavailable where no confirmed provider exists; this is not full P02/domain acceptance.

## S1 native attachment preview seam

`tables/general/attachmentPreview.ts` now projects an exactly owned native machine file into the existing authorized viewer's local `MediaPreviewItem`. It preserves source PK/model/id and filename label without making a page/segment/revision or applicability claim. The generated/assistant wire type is unchanged; other attachment owner types are not silently enabled. The existing indexed-media metadata/byte provider remains the authority. Unsupported/external files retain native links; unindexed or denied source access remains explicit. See `s1.md` for executed tests and remaining P14 review.
