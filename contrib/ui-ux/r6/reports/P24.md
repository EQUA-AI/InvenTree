## Native mapping and implementation

- `WorkOrderDetail` already owns separate Closeout and History panels. Standalone commands retain exactly `canonical_commands_enabled && !repair_packet`; packet work retains its owning packet link and completion authority. No second completion endpoint was introduced.
- `CloseoutPanel` had capture/proposal/decisions, usage/readings, readiness and effects queries, but always opened the Narrative→Review→Parts→Readings→Complete wizard. It also sent every decision as `edited` and reconstructed values from extraction rather than saved decisions.
- The prepared account, story, report preview/export and mapped final action are now direct. Narrative/Review/Parts remain native recovery controls. Known facts are a read projection: they neither prefill the mutually exclusive typed narrative input nor auto-create a capture. An active capture resumes in place; Dictate cannot replace it. A saved required-field correction must be recorded before completion.
- Native server decisions are `accepted`, `edited`, `rejected` (`DecisionEntrySerializer`, `_normalize_decision` in `services/closeout_capture.py`). Unchanged extracted fields now send `accepted`; a correction/manual field sends `edited`. Saved decisions, including rejection, take precedence on reload.
- Native `CloseoutCaptureRevision` and `WorkOrderCloseout` hold source narratives and accepted fields. The existing scoped capture list now includes retained revision ids, text, hashes, supersession, work version, author and time, prefetched as a batch. No write is performed by these reads. The overview adds immutable original accepted fields, content hash and completer alongside the existing effective amendment projection.
- Existing scoped amendments are displayed with original/new values, reason, requester, decider, status and times. Original accepted fields remain readable. No amendment-write UI or acceptance chore is added.
- `PreparedCloseout` shows known story/transcript references, account/source version, missing cause, material usage, unknown person-work time, optional downtime/follow-up drafts, failed and later saved readings, preview and a text download. Preview/download only read/export; they do not generate/approve/submit an account. Current supporting material/readings are explicitly distinguished from immutable accepted fields. This is a text account export, not a server-generated PDF service report.
- Physical reading entry moves to Verify & Return; Closeout reads the same `['closeout-readings', workId]` cache and links back. Both invalidate native readiness after a reading write. Completed work exposes readings read-only; renewed physical investigation needs the supported linked/reopened workflow. No physical operating/service authority is inferred.
- History remains a chronological event record, now with recorded actor id (or “Actor not recorded”). The actual COMPLETED event is labelled “Maintenance record updated”. Actorless events are not guessed to be automatic actions.
