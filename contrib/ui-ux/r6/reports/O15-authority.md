## Implemented behavior

**B1 — Plan & Safety.** Immutable `repair.GateAuthorityRecord` rows attach isolation points, permit numbers and access windows to existing repair-packet gates. They retain recorder/server recording time, actual observation time, effective start/expiry, source reference, statement/limits, version, superseded original and independent verifier/time where the gate requires it. Corrections append and reset verification. Verification appends with the original recorder/time plus the second person's separate attribution. No record confirms a native gate. Existing gate evaluation blocks recorded authority that expires, is released/revoked, lacks required independent verification, changes scope or loses its packet/asset ownership; a waiver cannot bypass that block.

**B2 — Verify & Return.** Distinct `tasks.OperationalAuthorityRecord` kinds record maintenance test acceptance, operating permission and observed return. Accepting a test creates neither operating permission nor an operating observation. Acceptance snapshots its source test rows; a later retest marks the basis changed without rewriting the accepted original. Maintenance requires native Work view/change and `tasks.execute_workorder`; operations require native Work view/change plus the explicit new `tasks.record_operating_authority` permission. Physical records also require the gate's own permission. No existing group is automatically promoted. Current role, active user, canonical Work/asset scope, gate and target are reauthorized before replaying a saved command. Work customer scope does not substitute for machine scope. Generic audit responses omit full O15 receipts; durable receipts remain intact for exact replay and authorized facts remain in scoped authority reads.

**B3 — Service restoration.** Operators can record machine/station duty, standby availability, redundancy and restrictions, or explicitly confirm/correct an existing telemetry observation. Bindings must already be active, approved and owned by the authorized Work machine or its authorized parent station. Source clock, quality, staleness and source activity remain separate from operator attribution/time. Confirmation pins the exact reading/binding/time and refuses stale, inactive, missing, future or uncertain readings; an explicit correction remains possible. Blank facts and absent tags stay Not recorded.

The local catalogue/registry contains `st`, `pc` and `MOTOR_ON_STATUS` context; no dedicated duty/standby/redundancy tag was found. Status encoding/polarity is not assumed: raw zero/false remains a raw reading, never OFF, available standby or redundancy. `telemetry-mapping.json` records catalogue/registry paths, hashes and limits. No live deployed binding audit was performed.

P19/P21/P23/P49 now consume these recorded facts with source, gate or asset identity, recorder and times. Existing condition-control, demonstrated full service/capacity, independent restriction clearance and obligations remain separate facts. Work completion or a recorded pass does not fill them.

## Commands, permissions and migrations

`GET /api/kanban/work-orders/{id}/operational-authority/` and overview `operational_authority.v1` return the scoped Work/version, recording capabilities, existing gates/targets, histories and telemetry context. `POST` accepts `operation` (`record` or `verify`), `expected_version`, the viewed `expected_context`, stable `idempotency_key`, `fields`, and optional `supersedes`. Recorder/verifier IDs and server recording times cannot be authored in the body. The existing Work command/event ledger preserves exact receipts and increments the Work version without changing lifecycle state. Foreign/unavailable Work is 404; current permission failures are 403; invalid bodies are 400; stale versions/key conflicts are 409.

The UI shares retained command state across panels/tabs by host/actor/Work. It preserves uncertain intent across reloads, reconciles only that original intent, and matches all authored receipt fields/actor/target/source/clocks before confirming a save. A later refusal cannot disprove an earlier uncertain save. Current capability/target failures suppress recording controls. Drafts pin their reviewed Work/context; scope, test or safety-contract drift requires explicit fresh review. All overview providers share the same captured source objects, preventing an older displayed scope/test from receiving a newer token during that GET. New records retain the checked basis; concurrent native changes surface drift rather than recapturing unseen sources. Telemetry confirm/correct also requires a per-reading token and pins the selected sample, including same-clock sequence replacements.

Reserved local migrations are `tasks/0033_operational_authority.py` (tasks 0032) and `repair/0012_operational_authority.py` (repair 0011 and tasks 0033).
