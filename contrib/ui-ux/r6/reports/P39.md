## Built

- An optional **Comparisons and display views** disclosure on pump Performance, retaining its mounted state through collapse. Native sections/forms remain available.
- Up to 12 selected mapped channels within the machine. Overlays require the same engineering role and a compatible scale via `units.ts`; other roles/units use separate synchronized native TrendCharts. Unknown/uncatalogued channels never acquire a shared engineering meaning merely from matching unit text. Native timestamps, quality breaks, nulls and recorded zeros are preserved through `rowsFor`.
- Other-machine candidates come only from the existing scoped `/api/assets/machines/` list, in 25-result search pages, with the same recorded asset type. A candidate's actual mapped signals must have matching roles and exact units. The current machine and candidate read the same frozen absolute display-time bounds. Matching roles/units are **technical compatibility only**: duty/load/configuration are explicitly unverified, and there is no operational ranking. No candidate is fabricated from an arbitrary id; list failure suppresses cached candidates. The list query is keyed by host, actor and auth generation.
- Before/after uses independently queried fixed WindowSpecs A and B. A freezes when the mode opens; B has independent date/time controls, the existing 24 h bound, and an explicit preceding-equal-window shortcut. That shortcut is labelled as a display choice and does not infer a repair boundary. Both windows keep their real absolute timestamps; they are not shifted into a fabricated repair effect. Within each origin, separate charts synchronize; A and B have distinct absolute time axes, without an elapsed-time overlay claim.
- Named personal per-machine display views reuse Mantine's existing `useLocalStorage` mechanism and the native Work-list precedent for actor/host isolation, with machine id added. Save/restore/delete; maximum 20 view names; stored fields are name, search, section and comparison binding IDs only. Choices remain unsaved until explicit Save. A read-back verifies local storage before showing saved success. Failed storage says unsaved; missing mappings are disclosed and never substituted. Views do not persist operational evidence, permissions, repair state or historical windows. Actor/host/machine changes reset local UI state. Browser-only scope is explicit.
- Existing registered per-user settings were inspected (`common/api.py` `UserSettingsDetail`, `InvenTreeUserSetting.SETTINGS`, `SettingsStates.tsx`): arbitrary keys are rejected, and no curated/shared view provider is registered. **Shared sets unavailable** is explicit. No new saved-view endpoint or registered setting was invented.
