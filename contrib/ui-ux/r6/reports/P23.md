## Built

The native Verify & Return panel consumes `verification_return.v1`. Measurement/inspection/verification executions retain their own immutable step criteria, application revision, current value, status, pass flag, recorder, time, note and result version. Numeric zero and false remain recorded values. A native pass is qualified as a recorded pass only when the source has a completed result, instructions, criteria and a usable value; unbounded numeric results and missing values remain not evaluated. Failed and not-applicable results remain distinct. A recorded pass does not establish technical acceptance.

Retained append-only failed/completed/reopened/not-applicable events are associated with the exact step execution, with actor, time, reason, version and evidence IDs. The native writer overwrites current values and does not retain previous attempt values or complete attempt conditions. Historical values stay explicitly unavailable; the current reading is never copied into an earlier failed attempt.

Separate native sections show physical results, controlled test permission, lockout/restoration records and operating return, service/redundancy, and the existing verification summary. Lockout applied/verified identities and verified/restored times are shown where recorded. A restored point is not job-wide release or clearance of independent restrictions. Test permission is not unrestricted operation, and an equipment test is not full service. Unknown authority, actual setup/conditions, technical acceptance, observed return and service state are visible and no authority control is offered. Existing Closeout is linked with panel/query context retained; its implementation is unchanged.
