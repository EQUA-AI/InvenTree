## Delivered behavior

**E1, P29/P45:** original audio or capture files are copied into native server media storage, selected by the registered AIMMS_CAPTURE_STORAGE_ALIAS in Django STORAGES (default: default). No Azure backend was configured or contacted. CaptureOriginal retains exact bytes, SHA-256, Work identity, recorder/time and optional client recording start/duration. Registered AIMMS_CAPTURE_MAX_BYTES defaults to 0, following the native INVENTREE_UPLOAD_MAX_SIZE policy; a positive value may impose a stricter byte limit, never bypass the native limit.

Closeout offers explicit microphone recording and existing-file upload. Local recording starts only on request, stops on hiding/closing the screen, and stays on the device until Save original media. A selected original must be confirmed saved or explicitly discarded before transcript acceptance. Failed saves retain the draft until discard or close; local media, timing and errors reset for a new session. Upload does not transcribe audio. Closeout records purpose-bound closeout-originals-v1 consent; legacy consent-v3-memory remains transcript-only and cannot authorize this upload route. The shared live-voice contract/disclosure is unchanged.

Every byte read reauthorizes the current native Work boundary. A voice original is private to its owner until commit. Committed stories retain the exact original, transcript revision and source ranges, including supplied segments. Story character offsets never become inferred audio times. Native observation artifacts retain a separate copy of an explicitly linked uploaded Work file, with supplied timing; external URLs are not fetched. Changing the native attachment later cannot replace that original. Missing media/timing remain explicit. File copies with protected voice roots also survive the existing retention purge atomically.

Supplied timestamps must contain a timezone. Their instant is normalized to UTC, including the fork's USE_TZ=False SQLite test mode; an explicit UTC offset is returned. A regression crosses client +05:30 and server Asia/Riyadh in both timezone modes. Unknown duration remains null; supplied zero remains zero.

**E2, P24/P50, clarified by the coordinator's O17 direction:** the existing atomic completion command freezes AcceptedCloseoutReport JSON and text at completion. The document preserves Work identity, completed fields, the consumed capture's revision/proposal/decision sources, original-media references/spans, material usage, saved readings and explicit unknown time/service facts. Other retained stories have their own labelled section and status; they are never called account sources. SHA-256 covers the exact downloadable canonical UTF-8 JSON envelope containing both document and text (sorted keys, compact separators, ensure_ascii=False). Completion actor/name/time and revision recorder/time are distinct. Closure acceptance is not inferred from completion; native verified_by/verified_at are shown separately when present. Applied amendments append attributed revisions with predecessor/amendment identity and preserve prior supporting evidence. They never overwrite earlier reports. Legacy completions are not reconstructed from today's supporting rows.

Instance and bulk ORM updates/deletes are rejected, related evidence is protected, and no update/delete report endpoint exists. This is application immutability; privileged direct database/storage administration is outside that guarantee. Completion/replay/rollback and amendment behavior use the existing native authorities. No second completion controller was introduced.

History and monitoring navigate exact report IDs/revisions. Work Closeout, including packet-owned Work, reads/downloads the frozen JSON/text separately from current supporting-record readers. Failed/denied reads hide cached report text and disable exports. Missing report metadata, a confirmed missing legacy snapshot and an unlisted requested report are distinct states. Readable story-source disclosures replace raw JSON; the exact source ranges remain in the snapshot export.

The only new migration is tasks/0036_capture_originals_accepted_reports.py, depending on tasks 0032 and voice 0011. It was applied only to disposable offline SQLite. No aichat migration is needed.
