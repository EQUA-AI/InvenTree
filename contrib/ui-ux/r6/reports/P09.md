## What was built

- **One shared trend reading** (`trendSamples.ts`, pure): every sample is kept at its own source time and sorted by time. A sample that cannot be drawn (not a number, or a number the source did not report `good`, the same rule as Performance's `usable` and the current-value rows) stays in the record as a null at its time. A gap beyond the display threshold becomes a display-only break (`measured: false`, never counted or shown as a sample). The display threshold reuses `gapThresholdMs`: max(2.5 times the measured interval, 15 seconds). Below three readings, the global expected interval is a server default, labelled as such; it is not a per-source fact.
- **120 x 28 row graph** (`SignalTrend.tsx`): x is now elapsed time across the read window (was sample index, which compressed a two-minute silence into one step and joined its edges). A new subpath starts after any undrawable reading or silence; a reading alone between two breaks is drawn as a dot. Width, height, `currentColor` stroke, 1.5 width, 0.75 opacity, round caps and the supplied-batch rules are unchanged.
- **Full blue AreaChart** (`SignalTrendChart.tsx`, `TrendPlot`): same Mantine AreaChart, `blue.6`, linear curve, 320 px, `connectNulls={false}`, dot rule (<= 60 drawn) and Parameter/Range/custom controls. The axis is now a numeric time axis over the selected window (was a category axis of formatted labels); rows carry timestamped nulls and silence breaks, so configured display breaks keep detected silences open; isolated readings get a dot on dense charts. Ticks fall on whole minutes and are sized to the plot (Performance pattern), so a phone shows a 5-minute grid.
- **Truthful states (screen 14):** recorded zero is a drawn line; a successful read with no readings is **No samples** (row) / "No samples in this window ... different from a recorded zero" (chart) — before, the row said "Too few samples"; a failed batch read is **Read failed** (before: "No trend", indistinguishable from a source without history); source outage/timeout says **Read failed**, no connector says **No trend**, unsupported history says **No history**, and a missing batch row says **Not returned**. Reasons are accessible through native buttons on keyboard focus and touch; the chart titles source failures **Could not read the source**. One "Gaps in this record" disclosure states silences, non-numeric and not-good readings and undated readings; when the server states no cadence it says silences are not marked.
- **Source/time context:** the chart caption names the selected window with seconds and the reader's time zone, and says when times were moved onto the dashboard clock (`display_shifted`). Raw unitless channels keep no unit (screen 13).
- **Backend (only missing fact):** trend reads (`trend/` and `trends/`) now state `cadence_seconds` (robust lower estimate of positive intervals from the binding's own sorted readings; null below three or with no positive gaps; corrected in review2 below) and `limits.expected_sample_interval_seconds`, mirroring the series read's existing fields. No sample is filled, resampled or reordered on the server.
- **Shared fix found while capturing:** `WorkOrderCreateModal` passed an inline `validate` object to Mantine form, so `setFieldValue` changed identity every render and the packet-toggle effect looped ("Maximum update depth exceeded", hundreds per page load) wherever the modal is mounted — the machine header and the Health tab included — starving the tab. The rules are now a module constant; behaviour is unchanged.

## Open items / missing facts

- **Report-by-exception sources:** the break threshold uses an observed interval estimate (else the global expected default). The shortest positive gap prevents silences dominating the estimate; a closely spaced observation can make the display break more readily, so this remains a display policy rather than a proven source rate. A source that writes only on change would need a per-source cadence/deadband fact, which no source model records. Not Blocked for the pump historian (5 s polled snapshots).
- Not-good-quality samples are drawn as breaks (same rule as Performance); that is a documented display decision, not a change to stored evidence.
- No R6 acceptance, live historian, deployment or human visual approval is claimed.

## Delegated-review correction — review2, finding 7 (20 October 2026)

**Status: built and tested for this correction**, against fixtures/offline services; final checks below. A single close pair previously made the minimum gap the cadence for a whole window. Health and Performance now share `measured_interval`: sort timestamps, discard nonpositive gaps, take the median of gaps at or below the overall median, and return no estimate below three readings. This resists an isolated close pair among minute readings while preserving the earlier sparse/alternating-silence regressions. It remains an observed interval estimate, never a configured physical sampling rate.

Incremental files: `src/backend/InvenTree/machine_health/services/{trends,series}.py`, `src/backend/InvenTree/machine_health/tests/test_trends.py`, `src/frontend/tests/s3/{healthFixtures.ts,pui_health_trends.spec.ts}`, and this report. The browser fixture mirrors the revised wire cadence. A regression verifies one continuous row path, native full path and expanded blue AreaChart for `[0,1,61,121,181,241,301]` seconds; backend tests cover 60 s and Health/Performance estimator parity (including duplicates and unsorted samples).
