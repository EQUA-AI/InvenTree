## Mapping before implementation

`WorkOrder.work_order_type` already records corrective / preventive / inspection / calibration / other. It is exposed by the overview/list. Procedure application checks the revision's work type against that Work. The types share `WorkOrderProcedureApplication`, immutable applied snapshots and `WorkOrderStepExecution`; there are no separate PM, inspection or calibration task stores. P21 supplies definitions/resources/revisions, while P23 supplies current measurement/inspection/verification results and retained outcome events. Instruction/control execution status was missing from the overview.

`CloseoutReading` already records label, **before/after** phase, original entry, normalized value/unit, expected minimum/maximum, warnings, verification state, disposition, linked step execution, recorder and time. Before/after is not an as-found/as-left designation. The native store also retains validated reading/attachment relations (`CloseoutReadingEvidence`), but the reading serializer does not expose per-reading artifact links; those are not fabricated here. Applied snapshot resources can reference a required tool/part; they do not identify the actual reference instrument used, its certificate, validity or test conditions. `ProcedureRevisionSource` authoring inputs are not frozen into the application snapshot and cannot silently become original applied-manual references. Work attachments remain with their native owner.

Standalone completion is the existing Closeout controller/complete command with native version, idempotency and site readiness. Native required fields are action, result and verification summary; cause is optional, so routine completion does not require an invented fault cause. Packet work retains its owning packet's completion path. P21/P23 authority, technical acceptance, operating/service permissions and physical return are explicitly unavailable where they lack providers. Software permissions, assignment, bounds and a completed task cannot replace them.

P41 already supplies Work-owned requests/revisions/artifacts and signed request-scoped Work focus. The existing repair-package create command retains source anomaly/thread/turn/evidence IDs, but has no originating routine Work/request relation. Creating chat actions explicitly bind no target Work in `_authorize_and_bind`; owner-bound thread/turn provenance is not a canonical shared routine-to-corrective relationship. Native scheduling dependencies are FS/SS/etc. scheduling constraints, not a fault-found origin relation. Full field/provider mapping: `data/devscratch/r6-s6/P51/provider-map.md`.

It reads all existing step kinds, original step snapshot, application revision/hash, current status/value/version and attribution, plus the native closeout-reading serializer under its existing feature flags. It reads no sibling Work records and writes nothing. Not-applicable dispositions do not reattribute old values/notes to their later recorder.
- One type-specific section in the existing Work panel: saved task list, expandable instructions/criteria/references, readings with original before/after vocabulary, recorded limits and recorder/time. Missing projection, disabled sources, successful empty records and missing values remain distinct. Zero and false are retained. Routine outcome copy says maintenance rather than repair.
- Native links to Plan & Safety references/qualified authority, Verify & Return readings/tests and the existing completion path. The native completion controller, readiness and packet boundary remain. No routine dashboard, second assistant, mandatory fault wizard, new completion command or automatic write is added.
- Optional fault-found disclosure opens the existing assistant on this original Work; when the URL selects a saved request owned by this Work, the existing launcher carries its exact request/version. Saving/publishing still requires the native approved proposal. Original tasks/readings and Work identity are preserved. Corrective discussion is offered without claiming the missing durable link was saved.
