## What was built

### Backend projection `investigation.v1`

`tasks/work_execution/investigation.py` is added to the work-order overview, so the page still renders from one read. It projects only the owning repair packet's saved records:

- **Explanation.** Read through `repair.schema.coerce_diagnosis`:
  - the likely cause and failure mode;
  - `preliminary`, taken only from the recorded human verification (`is_preliminary`), with `verified_by` and `verified_at`;
  - the analysis basis: status, authority (source alarm or a threshold in AIMMS), provider and version, generated time, data window and snapshot count, stale-signal count, and quality.
- **Evidence citations.** Each keeps its recorded relation (supports, contradicts or unknown); a v1 prose item stays "unknown". Also projected: alternatives, the diagnosis's proposed checks (`confirm_tests`) and technician amendments.
- **Findings with attribution.** Each carries `recorded_by`, created and updated times, and its verification (including disputed).
- **Intervention basis.** The current approved scope, its approver and time, step count and failure codes, plus how many superseded versions are retained.
- **Confidence is never projected.** The model's confidence number, which A08.2 rules out, is absent from the response; a test asserts this.
- **Requests.** `requests` is `{available: false, reason: 'no_provider'}`.
- **Finding history.** `finding_history: 'overwritten_in_place'` says that corrections overwrite findings.

### Frontend `DiagnoseProjection`

It sits on the Diagnose panel, with the pure module `execution/investigationProjection.ts` behind it. It shows, in order:

- **Current explanation.** It is labelled one of three ways:
  - "Preliminary — not technician verified", with "The initiating cause is not established… authorizes nothing";
  - "Verified by …", with the time;
  - "No explanation saved".

  Below the label are the analysis basis facts, each with "Not recorded" where missing, and one primary **Continue investigation** action.
- **Next check.**
  - An explicit "No saved investigation request" state, because no request with an owner, status or due time exists.
  - The diagnosis's proposed checks, labelled "Proposed by the diagnosis, not assigned, scheduled or confirmed".
- **Evidence and contradictions.**
  - Evidence is grouped as supports, contradicts, or related with the relation not established. Each item shows its value and unit (a recorded zero is shown as zero), observed time and snapshot reference or "No snapshot cited".
  - Disputed findings appear as an unresolved alert that says it does not block unrelated work.
  - Alternatives considered are listed.
- **Corrections.** Technician amendments with author and time, and the note that the server updates findings in place.
- **Intervention basis.** Version, earlier versions retained, approver and a link to Plan & Safety.
- **Native findings table.** The native `InvestigationSection` table stays underneath, unchanged.

### Continue investigation and fallbacks

- **`ContinueInvestigation`** (`execution/ContinueInvestigation.tsx`, reusable) opens the one existing assistant with the existing P02/P33 Work focus, at the shown `lifecycle_version`, with a return path to Diagnose.
  - Its caption says a specific request or finding is not carried into chat yet.
  - Opening it acknowledges or sends nothing by itself; a browser test checks this.
- **Fallbacks:**
  - Standalone work says no repair packet means no saved investigation, and keeps chat primary.
  - A server without the projection keeps the native findings view, plus a Continue investigation action.
- **Removed from the Work panel:** the "Confidence N%" badge in the native `WorkOrderProblemPanel`, per A08.2.
- **What Diagnose does not have:** no form, input, wizard, score or round counter. A browser test asserts there is no `input`/`textarea`/`select`/`form` and no `%`.
