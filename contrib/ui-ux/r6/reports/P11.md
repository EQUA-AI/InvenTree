## What was built

### S3-05: station view (StationPerformance) inventory and evidence
- New S3 harness page `playwright/s3-performance.html/.tsx`. It renders the native `PerformancePanel` for a pump or a station inside a `MemoryRouter` whose location is printed (`data-testid=destination`). It has fixture leave/back buttons. The shared S0 harness is untouched.
- New `tests/s3/stationFixtures.ts`. It answers only the station's signals, data-range, mimic bay list (`/station/17/mimic/`) and keyed series reads. The fixture has four bays (P1, P2, P10, P3); P10 is inactive and listed after P2, as in the mimic's key order.
- `pui_performance_station.spec.ts` records the inventory per run (KPI tiles, card titles, chart count, chips, table columns and rows) on desktop and phone, light and dark. It asserts every native form, plant numbering of the bays, bay links to each machine's own Performance tab, a single keyed read for the station and all bays, and that no State badge is clipped.
- **Found and fixed (red-before kept):**
  1. The native station view made two series reads per window: a keys-only read of the station's own points before the bay list arrived, then the same read again with every bay's keys. It now waits for the bay list. If the bay list fails, it still reads the station's own points.
  2. At 390 px the bay table squeezed its State badges to "R…" and "I…". The table now scrolls sideways at a minimum width (`Table.ScrollContainer`), and the State column keeps a minimum width.
- The station inventory is identical before and after on all four viewport/scheme combinations. The only differences are fixture values, which wobble per run.

### S3-07: dual-axis and shared-scale charts, audited against units
New `units.ts` (8 unit tests). It compares units as written ("degC" ≠ "°C"), never joins an empty unit to a stated one, and never rescales. S3-03's equivalence stays: W/var/VA share a power axis at the same SI prefix (MW/MVar), and `mW` is not read as `MW`.

| Pairing | Risk found | Change |
|---|---|---|
| Power / power factor; reactive power | Already fixed in S3-03. | Kept; verified that it is not split by the new guard. |
| Current / voltage, Excitation, Speed / status, Pressure / valves, Forebay / flow (`ParameterTrend`) | An axis could hold unlike units (line voltage kV beside phase voltages V; valve % beside mm) under the first member's label. | The first scale stays on each axis. Any other scale is drawn on its own trend in the same card, with "Drawn apart: X in kV, not V." Axis titles name the unit actually carried. |
| Sensor family cards (winding, core, bearings, cooling, vibration roles, draft tube …) | The axis, heatmap scale, bars and "highest now" assumed one unit. | A mixed-unit family becomes one card per unit, each with every native form, plus an explanation. |
| KPI "highest of" tiles (vibration, winding) | Ranked across units as plain numbers. Red-before: "190 degF, Highest of 4" among degC sensors. | Ranks the largest same-unit group and says "1 in degF not compared". |
| Cooling / air rise (ΔT) | Subtracted sensors in different units. | Only same-unit pairs are calculated. Refused pairs are named. If every pair is refused, the card stays and says so. |
| Station: power and flow by bay; forebay / surge / count | One axis labelled with the first bay's unit. | The largest same-unit group of bays is drawn; others get their own trend in the same card. The level card uses the same axis guard, and its legend is kept. |
| Station plant totals | Summed kW bays into MW totals. | Only one unit is summed, and the caption names the bays left out. |
| Station bay table | The column header used the first unit found, and every cell was printed under it. | The header uses the majority unit; a cell in another unit prints its own. |
| Relationship scatters | x and y are different quantities by design, each axis labelled. | None needed. |

- **P38 needs this (seen while reading the code; not part of P11):** the server caps one series read at `MAX_SERIES_TARGETS = 200` (`machine_health/services/series.py`). The pump view sends every binding plus 2 station keys in one read, so a machine with more than 198 mapped channels would get `400 TOO_MANY_TARGETS` for its whole history read. P38's 200- and 500-channel fixtures will hit this. P38 was not started.
