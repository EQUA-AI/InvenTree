Work, requests/artifacts, actions, closeout/follow-up updates, chat and Equipment consumers use these shared projections on desktop and phone. Absent authority/service records are explicitly **Not recorded**; no new authority record schema is assumed.
- Schema 3 on the existing owner-only signed `/threads/{id}/work-focus` receipt supports optional exact component and evidence references alongside existing v1 Work and v2 request identities. Standalone reference selection requires no fabricated Work. Reference positions are `reference_positions.v1`, not fitted-part identity; optional slots must belong to that position's family on that machine. Canonical slot PKs and a mapping fingerprint detect replacement. No live telemetry/Work-list changes are mistaken for geometry changes.
- Acknowledgement, stream preflight and locked intake re-read native roles, Work/request scope/revision, independent machine scope, exact position/slot and readable evidence. Foreign/unreadable/stale references refuse generically. Attachment focus uses native linked-model role + owner scope + existing metadata revision; media uses the existing indexed-byte provider, including actual source hash; reading focus pins mutable fields and evidence links with decimal normalization. Exact evidence is bounded to the named Work or machine; unrelated Part/step attachment launchers are not added.
- Receipts and boundary hashes stay private. Canonical results and owner reload preserve exact public IDs. Aggregate and independent component/evidence states use current/changed/unavailable; shared readers receive no private focus. All selected identities remain visible and source links are canonical. Existing `/chat`, `/chat/stream`, `/agui`, resend and explicit remove-selection behavior remain the single assistant contract.
- Equipment's launcher works from the model selection and schematic selection. A keyboard component list remains available if the optional renderer is loading. Selected position follows the canonical URL, including when an answer or Parts link returns to an already mounted panel; model/mode/label state is preserved. The reference-model qualifier remains visible. Closeout provides **Ask about this reading** for exactly revisioned source rows.
- Request publication stays an explicit technician approval flow under schema 3; focus does not save evidence. The workflow labels editable identifiers as untrusted data and explicitly refuses to treat evidence IDs as source content when no existing tool returns the exact facts.

## Review findings and dispositions

Coordinator follow-up under O12 confirmed the original signed/owner/live-authorization boundary. The five implementation findings are addressed without changing that boundary; prior handoff evidence below is preserved separately from the new `data/devscratch/r6-s0/P02/review/` results.

1. **Uploads lost on a reference-focused turn:** request focus retains wf8 and its explicit upload/publication note. Component/evidence-only text pins wf8 only without uploads; uploaded files route to the existing wf6 consumer. Explicit server pins keep priority. Regression coverage exercises component and evidence, with/without files, request uploads and explicit pins; a new native drawer case checks the file ID and signed receipt are sent together.
2. **Whole-file hashing and repeated reload checks:** focus compares the current indexed AttachmentIngest SHA with the native ingestion stamp, filename, size and exact storage modification time. Unknown/missing/drifted metadata is unavailable, with no byte-read fallback. Actual media streaming retains its full same-open-handle hash. Reload caches each distinct saved reference snapshot once. Regressions prohibit storage `open()` during acknowledgement/preflight/intake/reload, check one media resolution for repeated answers, and reject changed size/mtime/inactive ingestion/missing metadata. Cheap metadata comparison cannot detect out-of-band byte replacement that preserves both size and modification time; actual byte serving still verifies SHA and refuses it.
3. **Child loss incorrectly made the whole Work unavailable:** parent Work/request authorization and state are projected independently; references retain their own current/changed/unavailable states. Saved focus remains readable when the parent is readable, with stale/reference details. The Work chip keeps the canonical Work/request link and names unavailable child sources separately. Corrected backend expectations plus new light/dark desktop/390px and unit regressions cover this without weakening the existing truly-unavailable-Work spec.
4. **Reference loss hid readable proposals/rejection:** listing and `current=False` recheck only Work/request identity, permission and boundary; current publication still refreshes all coordinates. Regression cases cover deleted attachments, replaced media, inactive machines, listing/details/rejection remaining possible, full publication refusal and later scope revocation.
5. **False-positive refusal tests:** foreign machine uses its own valid revision and becomes acknowledgeable after a real native grant. A readable sibling-Work attachment is explicitly shown to pass native read authorization but fail the selected Work binding; it succeeds for its actual Work.
