## Built

- Capture create/decision saves retain the original version, key, payload and draft in actor/API/Work-bound session storage. Pending blocks another save; network/5xx/malformed receipts remain unconfirmed. Only an exact matching native receipt releases the operation. Recovery replays the original command. Refusal during recovery does not prove the earlier save failed.
- Conflicts show the retained draft and an explicit scoped latest read. Keeping draft values or taking saved values is deliberate; it prepares the form and never auto-saves. Failed/denied latest reads expose no protected comparison or replacement action. Inputs retain their original base version across background refreshes.
- Capture decisions now carry `expected_decision_version`, a hash of the current source revision, proposal and recorded decisions. The proposal's token is calculated from the same prefetched decision objects as its serialized values: a newer capture-list token cannot be paired with older proposal fields. HTTP requires this token; under the existing Work/capture locks a stale edit returns `CAPTURE_STALE_REVISION`. Exact idempotent replay still precedes token checks. Existing trusted internal service callers retain their compatibility contract; no schema migration or endpoint was added.
- Work attachment metadata GET exposes `expected_revision`. Native Work metadata PATCH requires that hash and compares it while holding the attachment row lock; stale/missing tokens return 409 without mutation. Native role and owner scope checks remain. The existing native modal retains its fields, disables another submission after a request failure, reads the authorized latest metadata and lets the user deliberately prepare a replacement. Enter-key submission uses the same disabled guard. Other model attachment edits retain their existing behavior.
- If an attachment has moved to another Work, recovery refuses to rebase the old form; it cannot silently move the attachment back through hidden owner fields. Work attachment/link creation retains the native form on refusal and blocks automatic or keyboard resubmission after uncertainty. The inline explanation owns handled failures without a duplicate generic HTTP-code toast. Real file transport/storage remains a separate P28 verification edge.
- Native attachment OPTIONS/background refresh previously refetched initial values and remounted field controllers, losing edited metadata. The opt-in Work form recovery preserves both values and mounted controllers after the first authorized load. Initial read errors remain visible; missing edit-revision capability disables saving. Other native forms retain their default behavior.
- Parts dispositions/reasons now live in the retained Closeout owner, survive step switches, keep their original row version and offer latest/draft reconciliation. Parts tables scroll within the native panel at phone widths.
- A failed background Work read retains the mounted workspace with a last-known warning. A denied/nonexistent response hides the protected workspace. Closeout source failures lock saves and remain distinct from an empty successful read.
- Reading entry retains all inputs on refusal or unconfirmed response. A verified 201/native id is required before clearing fields. Unknown append outcomes stay locked because the endpoint has no idempotency contract. Deviation entry distinguishes confirmed refusal (correction allowed) from uncertainty (draft retained and retry locked).
- Failed dictation review retains the transcript across modal dismissal/reopening. Cancel finishes before the modal resets its governed session. Successful commit clears the transcript. No audio storage, new recorder or neutral observation path is claimed.
- Reused P25's one final-update controller and the existing assistant's investigation command path. No duplicate completion or investigation editor was introduced.
