### Scope rules used below

- **M:** `require_machine_scope` / `scoped_machines` / `machine_scope_filter`: exact client grant, no inferred global scope, no free-text location/site authority. A customer-only grant does not authorize machines. Missing, unresolved or foreign detail returns 404.
- **W:** `require_work_order_scope` / `scoped_work_orders` / `work_order_scope_filter`: an explicit Work customer is the complete boundary; otherwise its machine client owns it. A client grant never covers customer-attributed Work. Unresolved/foreign details return 404; collections filter before counts/pagination.
- **R:** registry `authorized_client_ids`: active Client, exact client-only grant, no customer/mixed/site-qualified widening. Foreign detail is 404; an unconfigured actor resolver can return the native configuration denial (403).
- **P:** `scoped_repair_packets` / `require_repair_packet_scope`: a linked packet is authorized through its parent W and must name the same machine as that Work. Mismatched persisted packets are withheld. A packet without Work uses M. Every nested gate/finding belongs to that scoped packet.
- Default tests use the persisted `granted_client_scope_resolver`, real stored RuleSets/grants and fresh Django sessions. This resolver also requires Work view. Thus canonical scoped reads and indexed-media refusals can deliberately be **404**, rather than 403, for a user without that role. Explicit role APIs return 403. Independent supported resolvers isolate the separate Materials, Job Kit, Closeout, indexed-media and Work-focus role checks. A real customer resolver proves customer Work 200 while client Work and the asset remain 404.

## Fixes and test design

- **Materials role:** a real independent client resolver let an authenticated user with no Work role receive Materials 200. Red test retained; endpoint now requires native Work view before W lookup. Existing material stock-redaction and foreign-scope fixtures receive Work view explicitly, retaining no stock permission.
- **Finding UUID disclosure:** authorized packet writers received 400 for a foreign machine's snapshot and 404 for a missing UUID. Red test retained; nested lookup now filters `machine_id=packet.machine_id`. An own-snapshot positive control remains.
- **Mixed customer/client scope:** two red tests (eight failing assertions/subtests) proved that one resolver value containing both identities was rejected by exact-record checks but accepted by Work collections, machine/history filters and client-code retrieval. `scope_for_actor` now rejects that malformed identity centrally. Two separate valid grants remain supported. Dataclass/dict/tuple shapes and mixed-plus-valid inputs are covered. Registry's malformed-resolver response deliberately tightens from empty 200 to its native configuration-denial 403; foreign valid boundaries remain 404.
- **Stable planning intent:** inherited legacy HTTP helper minted a new key when absent, allowing an unkeyed planning write. This predates R6 and is documented as a contract tightening, not an R6-introduced role bypass. It now rejects absent/blank/mistyped/oversized keys. Existing successful scheduling/planner fixtures provide explicit keys.
- **Viewer affordances:** real browser red cases showed Closeout capture controls and Health/header Analyze/Acknowledge/Dismiss/Create/Start controls enabled. Server roles remain authoritative. UI now reads native CRUD roles for Health and native user-permission dictionaries for specialized Closeout actions; it does not infer custom capture/complete authority from CRUD change. Machine header changes are only disabled predicates, with native layout preserved.
- **Native exceptions retained (Closeout exception removed by the follow-up below):** Closeout reads now require native Work view even with an independent scope resolver. Media hides role revocation as 404. Legacy projections stay available with additive API flags off. A disabled source is disconnected/unhealthy but its authorized retained fresh observation can still have its recorded condition; disabling intake does not erase evidence or change timestamp/quality facts.
- **Read-only evidence:** SQL guard rejects INSERT/UPDATE/DELETE/DDL, including changes that preserve row counts, around all matrix reads and denied commands. Native default settings (including the error-page `_PENDING_MIGRATIONS` setting), synthetic records and login sessions are initialized before this guard; the assertion is about initialized application requests, not an uninitialized server's startup settings creation.
- **Matrix:** separately generated route/authority cases for anonymous, no-role, in-scope, foreign client, customer precedence, unresolved owner and feature-off; independent stock positive/redaction controls; nested occurrence/snapshot/request/capture mismatch; receipt actor/policy/thread/version/role/scope checks; hold/resume/capture/planning/investigation create/revise/artifact denied, missing-key, exact replay and conflicting-intent checks; post-success investigation revocation; packet read/action adapters before dispatch.
