## Screen and implementation

The user is the maintenance technician/engineer reviewing packet-owned Work in Closeout. The main task is to review the prepared internal maintenance account and issue one final update. The owner master design prompt and designprompt1 were applied within native React/Mantine routes, providers, permissions and safety boundaries. No installed image/OpenAI/skill-authoring skill applies to this change; no Figma or new dependency was used.

- Existing `POST /api/repair/packets/:id/close/` accepts a durable operation key and returns the standalone command receipt fields at the response root: Work, command, key, event, next version, correlation and closeout id, plus packet id in metadata. Legacy bodies without a key still work, and legacy packet response fields remain. No new endpoint, model or migration is required.
- New callers retain packet id, original Work id, expected version, key, capture id and exact account. The service locks packet then Work, checks permission/scope, and replays the original receipt before current version/gates. It refuses changed account, reason, version, capture or original Work. The existing packet return event binds new keys to their original Work; repointing cannot redirect an in-flight account. Historical Work-only hashes require the matching durable packet event and reason.
- `GET` on that same packet close URL returns native completion readiness with the packet capability and actual packet transition/return gates. It names packet and Work. The UI rejects mismatched identity and discards cached ready data after a refresh error. The query shares the canonical Work readiness invalidation prefix, including Verify & Return reading invalidation.
- Existing capture/decision URLs dispatch packet-owned writes through locked packet services. Accepted voice handoff uses the same ownership boundary. Permission, scope, version, decision revision, accepted transcript identity, capture-to-Work checks and active capture/voice locks remain authoritative. JSON cannot supply a packet capability; a different packet cannot authorize a capture. Direct standalone finalization of packet-owned Work remains refused.
- Packet-owned Work renders the existing `CloseoutPanel`, one `useWorkRecordUpdate` controller and unchanged `FinalUpdateAction`. Its retained intent fixes the native endpoint. Pending, matching-receipt success/time, refusal, stale comparison and uncertain reconciliation reuse P25's states. Work and Verify & Return contain navigation only; no proof modal or second confirmation was added.
- Native packet Closeout links to **Open Work Closeout**. The old packet close modal is no longer mounted. A packet without Work retains its distinct native Close Packet action. Verify & Return uses the existing shared reading component/cache; no P51 reading-controller refactor was made.

## Review findings and dispositions

Coordinator review findings 1–5 were accepted and fixed at the owning boundaries. **All five findings are fixed and their targeted checks passed.** The earlier passing runs above remain historical evidence. None of these checks grants product or deployment acceptance.

1. **Scope / Work existence oracle:** close now accepts a caller's Work id only when it is the packet's current Work or appears in this packet's own return-to-service history (including legacy events without a key). A scoped, nonlocking Work lookup and full service scope check precede the scoped Work-only row lock; scope is checked again under the lock. Unrelated, nonexistent, unresolved and foreign-scope ids have the same normal 404; scope failures in packet readiness/close are also mapped to 404. New regressions observe `QuerySet.select_for_update` and assert zero Work locks for refused ids, including foreign/nonexistent historical ids. This enforces the threat model's authorization and tenant scope boundary before acquisition of a Work lock; it grants no new trust to packet metadata. The existing repointing test now supplies a historical packet event so it still tests the definitive post-replay ownership refusal; its original no-write assertion is retained.
2. **Flags-off final action / circular navigation:** the native Work overview now exposes effective `closeout_wizard_enabled` (both deployment flags). Packet-owned Work always mounts the shared Closeout controller/action. When the wizard is explicitly disabled, a manual account uses the existing field controls and packet readiness without calling wizard endpoints. Capture, materials and readings are labelled not enabled/unavailable, never empty successful evidence; unexpected 404s while enabled still block. Disabling the wizard also cannot bypass an existing unfinished packet capture; that case has a backend regression. Disabled report sources are labelled not enabled instead of indefinitely loading. No modal, second confirmation or standalone packet completion was introduced. Backend tests use fresh packets for all four flag combinations and read the real native overview URL. Browser regressions cover all three disabled combinations from packet navigation through manual entry and matching receipt, in both themes and viewports, with zero wizard requests.
3. **Downtime validation:** the shared completion service validates new completions with `CompleteCommandSerializer` fields, after exact replay, preserving historical intent hashes and receipts. Fractional and negative downtime are refused without closeout/event writes; the input also disallows decimals. The same fields now govern packet and standalone persistence.
4. **Permanent uncertain state after owner changes:** completion ownership refusals raised strictly after replay (`PACKET_WORK_ORDER_CHANGED`, `PACKET_OWNS_LIFECYCLE`) are definitive stale/noncommit, including during reconciliation. Permission/scope/unknown responses remain uncertain during recovery. Storage is namespaced by packet; legacy Work-only entries are restored only for their immutable packet owner. Releasing a refusal retains an idle marker so an old legacy entry cannot reappear. New pure tests cover owner isolation, legacy restoration, definitive recovery and permission uncertainty.

Extraction checks packet then Work in both short transaction phases and in failure cleanup; no lock is held across the extractor call. Repointing during extraction refuses proposal persistence. Tests cover revise/abandon/extract with replay, missing/foreign ownership and mid-extraction repointing. Existing foreign-capture acceptance/consumption tests remain.
