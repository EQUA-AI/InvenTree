## What was built

### UI06 Machine Maintenance (screens 17, 18)
- The machine Maintenance tab now has two separate views, **Open work (N)** and **Completed history (N)**, each with its count. Counts come from a new read-only `GET /api/assets/machines/<pk>/work-summary/` (`machine_work_views.v1`).
  - The open count reuses the Machines list's own `_open_work_by_machine`: the same `OPEN` set (planned, ready, in_progress, on_hold, verifying), the active flag and `work_order_scope_filter`. The three counts therefore cannot disagree: Machines list, tab label and open list.
  - The completed count comes from the same `AssetMaintenanceRecord` queryset the native table pages through.
  - If the reader's Work scope cannot be resolved, the open count is `null` and the tab shows "not available", never zero. Responses are `private, no-store`, and a machine outside the reader's scope returns 404.
- **Open work** reads the native paginated Work list (`/api/kanban/work-orders/list/`) with `machine=<pk>` and a new strict `lifecycle_group=open` (any other value returns 400). The Board array is unchanged.
  - `WorkOrderTableSerializer` now carries read-only `affected_component` and `affected_component_ref`. The Board serializer is untouched.
  - Columns are Priority, Work (reference link and a two-line title), Component (or "Not recorded"), Lifecycle, Owner (typed user or legacy assignee) and Window (same-day windows compressed, plus due date). The table has no buttons, so work cannot be completed from it.
  - Search and pagination (25 per page) work, and the view, search and page live in the URL beside the Machines-list return state, so Back from a work order restores them.
  - Separate states cover loading, denied, failed (no cached rows), empty, empty search and "counts changed while loading" (offers to refresh both).
  - On phones the same fields are reorganized into one card per job.
- **Completed history** is the native `MaintenanceRecordTable`, unchanged except for three things:
  - It opts out of ambient page-URL filters (`boundToMachine` → `enableQueryFilters: false`). This fixes a real leak: the Machines-list `search=` on the machine URL was being sent as the maintenance table's search.
  - It has a new Component column from a new read-only `work_order_component` serializer field (withheld with the work order when the job is not visible).
  - Follow-up (residual condition) is now visible by default, and Type has a minimum width.
- When both views have rows, a neutral line says each job keeps its own outcome. Neither view is used as a verdict on the machine.
- The Machines list Work count ("2 open") now links to `/machines/machine/<pk>/maintenance/` and keeps the list's return state. This resolves the S1-28 note "the count is not linked yet".

### UI08 Fault History (screen 21)
- The native rollup is kept unchanged at the top. Below it, an **Occurrences** list comes from a new read-only `GET /api/assets/machines/<pk>/fault-history/occurrences/` (`fault_occurrences.v1`; `status=all|active|resolved`, limit/offset, max 100, strict 400). Each row has:
  - when it occurred and until when;
  - the event and finding: severity, title, source alarm code and id, and the record's own anomaly id;
  - the component, taken from the signals' dictionary-point slots and marked "unverified assignment" for draft slots;
  - the source and the number of retained snapshots;
  - the owning work (the anomaly's work order, plus a repair packet's own work order as related work when it differs);
  - the outcome (status and resolution note).
- **Nothing is invented.** An occurrence is an existing `MachineAnomaly`; no Fault record or FLT id is created, and a missing source id reads "No source alarm id".
- **Work is re-authorized per row** with `require_work_order_scope`. Out-of-scope work is withheld completely, with no id and no dead link.
- **Evidence** (and `?occurrence=<id>` links) opens one occurrence from `GET .../occurrences/<id>/`. It shows:
  - the original observation: first and last observed, who or what raised it (source alarm or a limit configured in AIMMS), acknowledgement, summary and metrics;
  - **every retained snapshot as captured**: window, capture time, quality and staleness at capture, reason, samples, source and content hash;
  - the work links.
- **Current readings are never read or shown here.** Instead a link points to the Health tab, and an occurrence with no snapshot says so rather than substituting today's values.
- Display-clock shifts are disclosed ("moved forward 442 d from the plant's own clock"), times state the browser timezone, and closing an occurrence returns focus to its trigger.

## Captures inspected and fixed
Captures are in `data/devscratch/r6-s3-machine-work/p12/captures/` (desktop and phone, light and dark, for maintenance open and completed views and for fault history and evidence).
- Phone open work hid lifecycle, owner and window behind an 860 px side scroll and clipped long titles. Fixed by switching to one card per job on phones.
- On phones the vertical view switcher was not full width inside a row. Fixed by stacking it full width.
- Adding columns truncated the Type badge to "CORRE…". Fixed with a minimum column width.
- The outcome badge "ACTIVE · ACKNO…" was truncated. Fixed: the badge now says "Active", with "Acknowledged, not resolved" on its own line.
- The Evidence trigger stretched to full width. Fixed with fit-content width.
- "Raised by source_alarm" showed a raw key. Fixed by labelling it "Source system alarm".
- The retained-sample table clipped "Retained value" on phones. Fixed by narrowing its minimum width.
- Fixture times were naive while capture times were in UTC, so a capture appeared hours after its window. Fixed: the fixtures now use aware times, as production does with `USE_TZ`, and the list states the browser timezone.
- Containment is asserted on each panel. The S0 harness's own destination line is wider than a phone; that is harness chrome and was left unchanged.

## Open items (missing facts)
- **Blocked: restriction modifier (UI06 open column).** There is no operating-restriction or physical-authority provider (D10). The column is not shown.
- **Blocked: Next action (open column).** There is no durable next-action provider, which matches the S1 record. Only Lifecycle is shown.
- **Blocked: Report link (completed column).** There is no service-report provider (D11 report history is unimplemented). Recorded outcome and Verified are shown instead.
- **Blocked: Report observation (UI08).** There is no neutral observation contract (work-list-contract.md item 4). Nothing is offered; renaming work creation would not establish one.
- **Supporting and contradicting evidence (UI08 expansion).** Relations exist only in an on-demand preliminary analysis, which captures new snapshots (a write). They are not persisted per occurrence, so they are not shown.
- **Component return context on the work order.** Back works through router history. The work-order page has no component-context parameter to carry.
- **A link from a work order's source alert to its occurrence.** It could use the new `?occurrence=<id>` target, but that is a change to `WorkOrderDetail` and is not made here.
- **Observed, not changed:** the existing `machine-health/.../anomalies/` endpoint returns `work_order` ids without a per-row Work-scope check, while the new occurrence endpoint applies one. This should be considered for D03/D04 review.
