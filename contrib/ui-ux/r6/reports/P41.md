## Canonical fields and rationale (O14)

`tasks.InvestigationRequest` is owned by `work_order`. Fields: generated `id`; `schema_version=1` (stored contract); optimistic `version` (independent request edits/evidence); authored `purpose` and `next_check`; nullable `priority`, unset by default; typed `required_artifacts` (kind, description, optional unit/conditions); enforced `Status` TextChoices; nullable `owner` and `next_checkpoint`; nullable same-Work `source_finding`; nullable `source_proposal` (packet id, check text and actual generation time); `blocked_reason`; `resolution`; `created_by` / `updated_by`; `created_at` / `updated_at`. Missing owner, checkpoint and priority remain unknown. Assigning a native Work reader does not establish expert qualification or an accepted handoff.

Status choices are exactly `open`, `answered`, `cannot_perform`, `pending_external`, `disputed`, `resolved`, enforced by serializer, model TextChoices and a database check constraint. The `(work_order, status)` index supports the queue. Ordering uses explicit priorities ascending / nulls last, then creation / id. Unprioritized requests cannot become the priority next check; an explicitly selected unprioritized request is labeled Selected request.

`tasks.InvestigationArtifact` has generated `id`, owning `request`, enforced `Kind` TextChoices (`observation`, `reading_set`, `photo`, `report`, `laboratory`, `check_result`) plus database check, validated typed `payload`, nullable native Work `attachment`, nullable same-request `supersedes`, actual `recorded_by`, and `created_at`. Corrections append; they do not edit originals. Reading sets retain named value/unit rows, time and conditions. Laboratory evidence retains sample/method/observed time/source/status/results; pending and absent results remain pending/unknown.

O14 adds three audit-only fields to the artifact: `source_turn_id` (plain string, no private-chat access granted), `source_proposal_id` (nullable UUID identifying the approved review), and `source_file` (nullable actual server file id/name/byte size/SHA-256/image/support metadata). Plain audit ids avoid a cross-store private-thread FK/retention dependency. Only the trusted executor can supply these fields; public command input cannot forge provenance. The hash proves which reviewed bytes were copied; no physical observation time, sample, method, status or file content is inferred from a filename.

The model cannot choose a Work/request/turn authority: those come from the verified saved turn. Only this proposal preparation is exposed to a native Work changer; ordinary readers receive authorized read tools, never an artifact executor. The source-turn + local key digest permits the same local key on a later round and prevents duplicate preparation on retry.
- Proposal creation saves a review only. The Approvals card shows exact request/revision, purpose, complete typed payload, any correction link, selected file name/size and a shared-Work disclosure. It uses the existing approval and dismissal UI; no competing response form. Only **Approve and share evidence** submits the exact preview hash. Revision refusals show the server's explicit nothing-saved explanation; 404/410 refusals state that this attempt shared no additional evidence. If scope refresh removes the private card, the Approvals area retains only that attempt's result, not the preview. Changing threads resets the notice. A network failure keeps the existing result-unknown wording. A successful saved receipt names actual artifact/request/technician; it refreshes the owning Work. Unresolved evidence is not a completed request or physical permission.
- On approval, fresh active/native/business/thread/Work/request authorization, revision and preview/file equality are checked before publication. The executor calls the canonical scoped idempotent artifact command with the approving technician and exact source turn/proposal. Repeated approval verifies and returns the stored command/artifact receipt rather than executing again. Refusal, expiry, changed business or policy scope, changed request/Work revision, altered file or changed preview saves no shared evidence and returns an explicit reason. Details/list/replay cannot disclose a revoked source.
- Supported publication is a bounded (20 MB) native Work copy of verified PNG/JPEG or PDF bytes from that exact source turn. The selected bytes are hashed in preview, rechecked and the same in-memory bytes are copied. Unsupported type/content produces a non-executable review explicitly saying nothing will be saved. Arbitrary paths, foreign/not-on-turn uploads and symlinks refuse. The private original stays private; unselected chat text/files are not promoted. Database rollback and storage cleanup cover canonical command or receipt-save failure. This is offline native-file testing, not deployed storage/codec acceptance.
- Explicit approved `check_result` outcomes `cannot_perform`, `disputed` and `pending` update only their exact request to unresolved status/reason. They do not invent owner/checkpoint, invalidate siblings, clear an earlier blocker after a later reading, resolve the request or change Work lifecycle. Resolution still needs explicit owner/explanation and current required final/performed artifacts; resolved requests must explicitly reopen before more evidence.
