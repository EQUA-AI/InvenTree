# P40 — Bounded case windows and retained-evidence provenance

Status: **built and tested for the assigned Performance/Fault History scope; Health adoption intentionally handed off** to its owning checkout. The initial host-browser blocker is resolved below. No R6 acceptance or deployed historian claim. All changes remain uncommitted.

## Built

- A reusable `assets/investigation/` module. Pure window validation, explicit contiguous case slices, link parsing and canonical navigation links. Performance slices stay at most 24 h. Consumers can choose a smaller actual endpoint limit; a unit test covers Health's 6 h trend bound. Setting or stepping through a case span does not read it automatically; **Read this slice** reads only the selected bounded slice. No auto-prefetch of an entire case, infinite-history promise or source-extent-as-data claim.
- Pump and station Performance accept `history_from` / `history_to` links as initial fixed windows, with Live off. Malformed/increasing-over-24 h links request no history and offer explicit recovery. Native manual range/zoom/live choices clear the old linked bounds. An arriving valid link can update the same mounted panel. Existing custom-window maximum is unchanged.
- History provenance identifies actual source, returned window/browser timezone, resolution, complete versus sampled mode, reported limits, point budget, extent metadata and display-clock shifts. It separates pump current KPI/bar/evaluation origins from selected-window trends. Station captions identify current source tiles versus calculated window totals/tables. Comparison reads use their selected origin only. Existing null/quality/silence gap adapters are reused; no synthetic samples, interpolation, transients or filled gaps are added.
- Aggregate history uses bounded batches with one common fetch-time interval and point budget. Successful sibling batches remain visible after a partial network failure, with an explicit **Partial history read** warning and Retry. Total failure never becomes successful empty history. Incoherent machine/window/mode/slots or clock offsets beyond one second fail only that batch; measured resolution/cadence stays attached per batch (review 2 below). No placeholder data crosses machine or target-set identities. Requests now consume the query AbortSignal (P11's historical “not cancelled” note is superseded).
- Multi-batch live/mode copy avoids describing the first batch's document count as the whole read. It states that batches may repeat source work and that no flat payload/cost/latency follows from aggregation. Single-batch native copy is preserved.
- P12 Fault History's `renderInvestigation` slot is wired through `FaultHistoryPanel`. The opened/re-authorized occurrence provides its actual first/last observation bounds and retained snapshots. Point/undated occurrences do not get an invented duration. Long observed spans offer explicit slices. Snapshot-source links use recorded windows; a snapshot longer than 24 h links only its first bounded slice, labelled as such.
- Performance rechecks occurrence references through the existing occurrence detail endpoint. Missing/denied/mismatched evidence produces an explicit unavailable state; no other snapshot or current reading is substituted. Retained id, source, capture/window, content hash and capture-time quality/staleness stay distinguishable from a new source read. No snapshot capture/write endpoint is called.
