## Built and mapped

The prepared Closeout account now contains a native material-custody disclosure. It reuses P22's `WorkMaterialsPanel`, existing scoped materials endpoint, Part/Stock links and `['work-order-materials', id]` query. The disclosure reads only when requested and stays mounted through collapse; initial Closeout keeps its four native resource reads on a server without an active proposal. Native links return to **Closeout**, with that label, when opened there.

Requirements, reservation/issue/closure facts and each recorder/time retain P22 semantics. Loose usage rows now show their actual stock identity/serial/lot through the same permission-aware StockLabel used by allocated rows. Their heading is neutral **Material rows without a linked reservation**: an unresolved row is not described as recorded consumption. The actual native state, disposition and variance reason remain visible; no new movement or disposition writer was added.

Native reconciliation controls remain available behind the existing recovery disclosure. Retained-for-analysis, repair/refurbishment, quarantine release, removed/fitted-instance links and warranty/core context are not supplied by this readout; the UI says so. It never maps them to returned/consumed/scrapped enum values. A resolved-by recorder is explicitly distinguished from an assigned discrepancy owner. Missing owners, business records and checkpoints remain unavailable.

P27's assignment/time projection is reused in a separate disclosure, preserving native timestamps and static assignment wall elapsed. Attributed intervals and coverage remain unavailable/unknown. Optional account downtime retains an entered zero but starts blank; it is explicitly separate from verified service downtime, whose outage interval/service-impact source is unavailable. No timer, activity selector, browser-derived labor or zero service outage is introduced.
