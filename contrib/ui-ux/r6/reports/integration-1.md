## Coordinator correction (agent verification, 20 October 2026)

An adversarial check of this report corrected the attribution: 12 of the 14 backend failures (MachineRequiredOnCreateTest create/partial-update/reassign, all four DependencyApiTest cases, all three ManualDoneMoveTest cases and ScheduleWindowConflictApiTest) are NOT merge regressions. They already fail at the pre-P32 base 1610c07c3, because 4d7a1389c (19 October) put the board, detail, schedule and dependency views behind scoped_work_orders / _require_candidate_scope, and TESTING forces AIMMS_MAINTENANCE_SCOPE_RESOLVER=None, so a superuser with no maintenance scope and a client-less machine gets 404 or an empty list. Only test_create_with_an_unknown_machine_is_rejected (P32 contract B), test_current_packet_safety_can_refuse_an_already_committed_replay (P26 replay order) and test_original_receipt_survives_packet_repointing (P26 with P32's packet-machine rule) belong to this merge. The fixture corrections stand (every real machine has a client), but the green suites model only machine-only Work.

Open owner decision raised by the same check (not changed here): under the production resolver (granted_client_scope_resolver) Work with an explicit customer is reachable by no API user, superusers included, because no resolver produces customer scopes. In the 20 October copy of the Azure database that is 1,393 of 1,550 Work orders (1,388 for customer "Zen Solar", 87 not closed); the 3 orders with neither customer nor machine are also unreachable. The deployed (older) line does not scope these views, so deploying inventTree-aniket would hide them. This needs an owner decision before deployment (see HANDOFF).
